AgentFactory — Vertical AI Agent Starter Kits

Blueprints for building production-oriented AI agents on AWS. Each kit gives you the reference architecture, the build contract, the acceptance tests, and the business case for a specific industry problem — so you can go from pattern to deployed agent in days, not months.

Read this first: these kits are specs, not code drops

Most kits here do not contain the agent's source code. A kit is the design and the contract — it tells you and your coding agent exactly what to build, why each architectural choice was made, and how to verify the result. You implement it in your own AWS account.

That's deliberate. These patterns get adapted to your data, schemas, compliance posture, and integrations anyway, so the durable value is in the architecture and the decision rationale rather than a fork of someone else's repo. AGENTS.md and build-spec/ are written to be handed straight to a coding agent.

Two exceptions if you want running code fastest: intelligent-ticket-triage ships a working CloudFormation stack and Lambda tools, and manufacturing-operations-hub points at an MIT-licensed AWS sample you can clone.

What we're solving for
Teams adopting agents hit three sequential blockers. A kit addresses all three.
1

"What should we build?"

You know AI agents matter but picking which workflow to automate is the hard part. A generic capabilities overview doesn't help; vertical-specific patterns with a stated ideal customer do.

2

"How do we build it?"

Your developers can write application code but agent orchestration, retrieval configuration, and guardrail setup are unfamiliar. The gap between demo and production is where projects die.

3

"How do we justify it?"

Leadership wants a business case before funding. Each kit ships an ROI model with explicit assumptions you can re-run with your own numbers.

How to use a kit
Clone the repo, pick a kit, hand it to your coding agent.
Step 1

Pick a kit

Browse the kit folders and read README.md and kit.json — the problem it solves, the AWS services, the ideal customer, and the disqualifiers.

Step 2

Hand it to a coding agent

Open the folder in Kiro, Claude Code, Cursor, or Codex and point it at AGENTS.md plus build-spec/. The spec states requirements, architecture decisions, and deployment targets.

Step 3

Deploy and verify

Deploy into your own AWS account, then run the kit's acceptance tests to prove the build behaves — including guardrails and human-in-the-loop paths.

Before you deploy

Implementing a kit creates real, billable AWS resources — Bedrock invocations, Lambda, storage, vector stores — in your own account. Review the architecture and the AWS Pricing Calculator first, and tear down what you're not using.

ROI figures are illustrative models with stated assumptions, not guarantees. Each kit documents its inputs so you can re-run the math with your own volumes and labor rates.

Kits are provided as-is, without warranty. You own the infrastructure, configuration, and data in your account. A kit is a starting point, not a compliance-certified product — review security, data handling, guardrails, and regulatory requirements for your use case before production. Several kits deliberately keep a human in the loop for consequential decisions; preserve that.
